Техническое задание
Система автоматической публикации товаров одежды в Telegram и Instagram с использованием GPT
1. Цель проекта
Разработать автоматизированную систему, которая ежедневно, без участия человека:

Получает данные о товарах одежды через сторонний API-агрегатор (Zara, Mango и, в будущем, другие бренды).
Отбирает и обрабатывает товары с помощью GPT согласно настраиваемому промпту.
Рассчитывает цену продажи (цена магазина + наценка).
Формирует готовый пост (фото + описание + цена).
Публикует пост в Telegram и Instagram.
Исключает повторную публикацию одного и того же товара.
Участие заказчика после запуска ограничивается:

редактированием промпта для GPT;
изменением размера наценки;
изменением расписания публикаций.
Всё остальное система выполняет автономно.

2. Источник данных о товарах
Данные о товарах (фото, название, цена, ссылка, ID, наличие) поступают через сторонний API-агрегатор (не собственный парсинг сайтов).

Необходимо уточнить и задокументировать у провайдера API до начала разработки:

Параметр	Что нужно узнать
Endpoint / метод	REST, вебхук или polling
Формат ответа	фото (URL или файл), название, цена, валюта, ссылка на товар, ID товара, наличие
Частота обновления каталога	раз в день / в реальном времени
Лимиты запросов	в день/месяц, стоимость сверх лимита
Формат авторизации	API key / OAuth / др.
Формат фото	прямой публичный HTTPS-URL или файл
Поддерживаемые магазины	только Zara/Mango или шире
Возможность добавления новых магазинов	через тот же API или нет
Система должна быть спроектирована так, чтобы источник данных был отдельным модулем (адаптером), который можно заменить или расширить без переписывания остальной логики.

3. Архитектура пайплайна
[Сторонний API] → получение товаров
        ↓
[Дедупликация] → сверка с БД по external_id, отсев уже опубликованных
        ↓
[GPT: анализ и отбор] → выбор лучших товаров согласно промпту
        ↓
[GPT: генерация описания] → короткий текст поста
        ↓
[Расчёт цены] → цена_магазина + наценка (наценка из конфига)
        ↓
[Формирование поста] → фото + текст + цена
        ↓
[Публикация] → Telegram Bot API + Instagram Graph API
        ↓
[Запись в БД] → статус "опубликовано", timestamp, ID постов
4. Функциональные требования
4.1 Получение товаров
Система получает список товаров от API-агрегатора по расписанию (см. п. 4.6).
Из ответа извлекаются: фото, название, цена, валюта, ссылка на товар, уникальный ID, наличие.
Товары, уже присутствующие в БД со статусом "опубликован", отбрасываются на этом этапе (дедупликация по external_id).
4.2 Анализ и отбор через GPT
Отобранные товары (фото + название + цена) передаются в GPT.
GPT анализирует товары согласно промпту, который хранится вне кода, в отдельном текстовом файле (например, prompt.txt).
Промпт читается системой заново при каждом запуске цикла публикации — без перезапуска сервиса.
GPT возвращает: список отобранных товаров + короткое описание для каждого.
Формат ответа GPT — строго структурированный (JSON), чтобы его можно было однозначно распарсить.
Максимальное количество товаров, отбираемых за один прогон — настраиваемый параметр в конфиге.
4.3 Расчёт цены
Формула: цена_продажи = цена_магазина + наценка.
Размер наценки хранится в конфигурационном файле и может быть изменён без изменения кода.
Если валюта магазина отличается от валюты продажи — требуется конвертация (уточнить у заказчика: нужен ли динамический курс или фиксированный, задаваемый в конфиге).
4.4 Формирование поста
Пост включает: фото товара, сгенерированное GPT описание, итоговую цену, (опционально) ссылку на товар.
Формат поста для Telegram и Instagram может немного отличаться технически (ограничения длины текста, поддержка ссылок), но содержательно — идентичен.
4.5 Публикация
Telegram:

Публикация через Telegram Bot API в заданный канал/группу.
Пост включает фото, описание, цену.
Instagram:

Публикация через Instagram Graph API (требуется Business/Creator аккаунт, привязанный к Facebook-странице, и прохождение App Review у Meta для нужных разрешений — это отдельный процесс, закладывается в сроки проекта).
Instagram Graph API принимает только публично доступный HTTPS-URL изображения, не файл напрямую. Если сторонний API-агрегатор не отдаёт прямые ссылки на фото, необходим промежуточный хостинг (например, S3 или аналог) — уточнить это в п. 2.
4.6 Расписание
Время публикаций и количество публикаций в день задаются в конфигурационном файле.
Изменение расписания применяется без перезапуска кода (перечитывается планировщиком).
Технически: cron-подобный планировщик (например, APScheduler) с параметрами из конфига.
4.7 Защита от повторной публикации
Уникальный external_id товара сохраняется в БД при публикации.
Перед публикацией система проверяет, не был ли товар уже опубликован.
4.8 Логирование и ошибки
Все ошибки (сбой запроса к стороннему API, ошибка GPT, ошибка публикации в Telegram/Instagram) записываются в лог с указанием: времени, источника ошибки, текста ошибки, затронутого товара (если применимо).
Логи хранятся в файле или таблице БД.
Рекомендуется: критические ошибки (например, публикация не удалась после всех retry) дополнительно отправлять уведомлением админу в Telegram.
Для вызовов внешних API (агрегатор, OpenAI, Telegram, Instagram) — retry с экспоненциальной задержкой при временных сбоях.
4.9 Тестовый режим (dry-run)
Флаг в конфигурации, позволяющий прогнать весь цикл (получение → GPT → формирование поста) без реальной публикации — для проверки результата перед включением в продакшн.
5. Настройки (без изменения кода)
Все параметры ниже должны находиться в конфигурационных файлах (.env, config.yaml/config.json) и применяться без правки исходного кода:

API-ключ стороннего агрегатора товаров;
OpenAI API Key;
Telegram Bot Token и ID канала;
Instagram Graph API токен и ID аккаунта;
путь к файлу промпта (prompt.txt);
размер наценки;
расписание публикаций (время, количество постов в день);
лимит товаров на один прогон;
курс/логика конвертации валют (если применимо);
флаг dry-run (вкл/выкл).
6. Структура данных (БД)
Рекомендуемая схема таблицы products:

Поле	Тип	Описание
id	PK	внутренний ID
external_id	string, unique	ID товара от стороннего API
source	string	Zara / Mango / др.
title	string	название товара
price_original	decimal	цена от магазина
currency_original	string	валюта магазина
price_final	decimal	цена продажи (с наценкой)
photo_url	string	ссылка на фото
description_gpt	text	описание, сгенерированное GPT
product_url	string	ссылка на товар
status	enum	new / selected / published / failed
telegram_post_id	string, nullable	ID поста в Telegram
instagram_post_id	string, nullable	ID поста в Instagram
published_at	timestamp, nullable	дата публикации
created_at	timestamp	дата добавления в систему
БД: SQLite (для старта) или PostgreSQL (если планируется масштабирование/несколько инстансов).

7. Технологический стек
Python 3.x
OpenAI API (модель — уточнить/задать в конфиге, не хардкодить)
Telegram Bot API
Instagram Graph API
SQLite / PostgreSQL
APScheduler (или аналог) для расписания
(Опционально) S3-совместимое хранилище — если сторонний API не отдаёт публичные URL фото
Playwright и парсинг сайтов не требуются, так как данные о товарах поступают через сторонний API-агрегатор.

8. Требования к расширяемости
Код должен быть спроектирован так, чтобы можно было без значительных переработок:

добавить новые источники товаров (новые магазины/API) — через единый интерфейс адаптера источника данных;
заменить GPT-провайдера на другую модель — через единый интерфейс вызова LLM;
добавить новые социальные сети для публикации — через единый интерфейс публикатора (publisher).
9. Юридические и организационные аспекты
Вся ответственность за использование данных, полученных через сторонний API-агрегатор (включая фото и информацию о товарах), в коммерческих целях лежит на заказчике. Необходимо отдельно проверить условия использования (Terms of Service) этого API-агрегатора на предмет коммерческого использования данных.
Публикация в Instagram через Graph API требует прохождения проверки приложения (App Review) в Meta for Developers — сроки этого процесса не контролируются разработчиком и должны закладываться в общий план проекта отдельно.
10. Открытые вопросы (уточнить перед стартом разработки)
Название/документация стороннего API-агрегатора товаров.
Нужна ли ручная модерация поста перед публикацией (хотя бы на начальном этапе), или публикация полностью автоматическая с первого дня.
Логика конвертации валют, если магазин и площадка продажи используют разные валюты.
Лимит на количество публикуемых товаров в день (помимо расписания).
Куда именно отправляются критические уведомления об ошибках (Telegram-бот админу, email и т.п.).
11. Критерии приёмки
Система считается готовой, когда:

 Товары автоматически получаются от стороннего API по расписанию;
 Промпт для GPT редактируется в отдельном файле и применяется без перезапуска сервиса;
 Наценка и расписание меняются через конфиг без изменения кода;
 Товар не публикуется повторно;
 Пост успешно публикуется в Telegram и Instagram автоматически;
 Ошибки фиксируются в логах;
 Dry-run режим позволяет проверить цикл без реальной публикации;
 Добавление нового источника/соцсети/LLM не требует переписывания всей системы.
